# Names for both ears, measured 2026-08-18

The question: what should the second ear (WhisperKit, `large-v3-v20240930_626MB`,
the one shipped in 1.20.0) be told before it listens, and what does that cost?
Whisper takes a "previous text" prompt (`DecodingOptions.promptTokens`); a list
of names there is the standard way to bias it toward a vocabulary. Every prompt
token is one decoder step, so the prompt is not free.

Method: `whisperkit-cli transcribe` (argmax OSS 1.1.0, homebrew) on the 30 clips
of Set E (`~/Desktop/chalant-corpus/audio-E`, the founder's voice, sentences
dense with the founder's names: Kizu, Aatram, Gangothri, Jonnalagadda, Wispr,
Superwhisper, PostHog, Vercel...), converted to 16 kHz mono WAV, one clip per
process (folder mode with concurrent workers misattributes reports across files;
seen and discarded). Same decode options as `BetterHearing.hear`. Word error
rate after lowercasing and dropping punctuation, against `desired` in
`manifest.jsonl`. Timings are the report's `fullPipeline`, per clip, median and
p90, on this Mac (MacBook Air M3, macOS 26). Apple's raw engine on the same
clips (`transcribe <file> en_US`, no vocabulary layer) is the reference the
sound-alike selection was fed.

## Results

| prompt | names | WER | median s | p90 s |
|---|---|---|---|---|
| none (what 1.20.1 ships) | 0 | 29.9% | 0.91 | 0.97 |
| every hand-kept name (`corpus/terms-canonical.txt`) | 34 | 18.6% | 2.17 | 2.43 |
| the same 34 plus 66 contact-like names (100) | 100 | 18.6% | 2.10 | 2.26 |
| top 12 names | 12 | 15.2% | 1.44 | 1.52 |
| top 12 names, trailing period | 12 | 14.7% | 1.42 | 1.49 |
| top 20 names, trailing period | 20 | 14.7% | 1.70 | 1.77 |
| top 12 + names phonetically near Apple's words, floor 0.60, up to 8, from an 88-name tail | ≤20 | 10.0% | 1.73 | 1.79 |
| same, floor 0.75, probes of 4+ letters | ≤20 | 10.0% | 1.58 | 1.76 |
| **the shipping selector (`NameHints.select`), per clip** | ≤20 | **10.0%** | **1.56** | 2.28 |

The 88-name tail for the last three rows was the 22 hand-kept names not in the
top 12, mixed with 66 ordinary first names (Priya, Sanjay, Michael, Jennifer…),
shuffled once: the shape of a real Contacts list. Per-clip prompts were built
from Apple's raw transcript of that clip.

## What it says

1. **More names is worse, and slower.** 34 names heard worse than 12 (18.6%
   against 14.7%) and cost 0.75 s more. The 100-name row equals the 34-name row
   because WhisperKit keeps only the last 223 prompt tokens, so the extra 66
   were silently dropped: a long list does not even reach the model.
2. **A name earns its slot by sounding like something the first ear heard.**
   Adding, per utterance, the tail names within 0.75 phonetic similarity of any
   4+ letter word Apple produced (or of two adjacent words run together, for
   names Apple splits: "friction lens") took the ear from 14.7% to 10.0% at
   +0.15 s. That is what let Vercel, Supabase, SpeechAnalyzer, Sara and appcast
   in only for the sentences that said them.
3. **Cost is ~13 ms per prompt token on this Mac** (2.17 s − 0.91 s over ~95
   tokens). Twenty names is about 60 tokens, +0.6 s. The hearing swap's ceiling
   is 6 s and the swap arrives ~1.9 s after release today, so there is room, but
   not for a hundred names.
4. The trailing period cost nothing and matched the ear's own punctuation
   (without it, some clips came back with no final period). Kept.
5. What is left at 10.0%: Sarah/Sara (both in the prompt, unresolvable by
   sound), "Wispr" against the real word "whisper", "N's" for "Ns", and one clip
   whose audio genuinely has a trailing sentence.

## What was built from it

- `NameHints.select` (Core, pure, 8 tests): standing names first, then the pool
  names that sound like the utterance, capped at 20 for the prompt and 100 for
  the phonetic pass (§0.13), at most 40 of the 100 from Contacts.
- `Names` (app): the standing list is typed names (`Vocabulary`, "Add a name")
  then learned names (`LearnedTerms`); the pool is `ContactNames`.
- `ContactNames`: given, family, nickname, organization, only when macOS already
  allows, dictionary words dropped by asking the spell checker about the
  LOWERCASED name (it accepts "Priya" and "priya" differently: measured on this
  Mac, "priya"/"ravi"/"sarah" rejected, "rose"/"will"/"grace" accepted).
- `BetterHearing.hear(_:hints:)`: `promptTokens` encoded as WhisperKit's own
  CLI does (leading space, special tokens filtered).
